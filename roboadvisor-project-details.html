Structured Financial QA with LLMs: Fine-Tuning vs. Code-Augmented Retrieval

Team Alperen Çağlayan · Saliha Nur Gökçe · Değer Ayata
My Role Co-author — RAG pipeline design, ragenh architecture, evaluation framework
Venue IEEE ISTAS 2025
Data BIST100 companies, 2008–2025 (KAP / Public Disclosure Platform)
Tools LLaMA 3 8B · LoRA · FAISS · sentence-transformers · HuggingFace PEFT

Overview

Comparative study of two LLM adaptation strategies for Turkish corporate financial question answering. The core design question: when working with structured tabular financial data in a low-resource language, is it better to adapt the model's weights (fine-tuning) or to adapt its context (retrieval)?

The system is built as a modular pipeline where each financial domain — liquidity, investment planning, debt strategy — operates as an independent QA module. Source data covers balance sheets and income statements from Turkish BIST100 companies (2008–2025), with derived financial ratios and temporal trends computed from KAP disclosures.

Architecture & Methods

  • Fine-tuning (LLaMA 3 8B + LoRA): instruction-tuned on Turkish financial prompts using HuggingFace PEFT with LoRA adapters. Trained to understand financial question structure and produce domain-aligned outputs without external context.
  • Standard RAG: sentence-transformers embeddings + FAISS vector search. Relevant financial passages retrieved and prepended to the prompt at inference time. Strong on direct extraction; weaker on multi-step numeric reasoning.
  • ragenh (enhanced RAG): pandas DataFrames integrated directly into the retrieval loop. The model generates executable Python code for table lookups, numeric comparisons, and temporal aggregations — combining retrieval, reasoning, and code execution in one step.
  • Evaluation metrics: ROUGE-L (lexical), BERTScore F1 (semantic, Turkish embeddings), Number Match Score (numeric accuracy), Trend Direction Agreement (temporal consistency)

Key Findings

0.286

ragenh ROUGE-L on opinion-based tasks — best overall (fine-tune: 0.234)

0.591

ragenh BERTScore F1 on opinion-based tasks (fine-tune: 0.539)

0.534

ragenh Number Match Score — best numeric accuracy across all methods

No single method dominates across all task types. Fine-tuning is strongest on trend and directional questions, where the model's adapted priors about financial language matter most. ragenh wins on opinion-based and multi-step reasoning queries, where structured tabular access outweighs language fluency. Task type determines optimal architecture.
