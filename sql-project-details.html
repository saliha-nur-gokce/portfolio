Solo · SQL + BI Project

Marketing Analytics Dashboard

Role Solo — data generation, schema design, SQL automation, BI reporting
Stack Python · MySQL · Power BI · DAX
Schema 13 interrelated tables with full referential integrity

Overview

End-to-end e-commerce analytics system built without an existing dataset — the data itself was generated from scratch in Python to reflect realistic e-commerce sales structures, marketing funnels, and advertising campaign dynamics. The goal was to build the kind of analytics environment a growth-stage e-commerce company would actually use to answer questions about customer behavior, campaign ROI, and revenue attribution.

The full pipeline: synthetic data generation → relational schema design in MySQL → automation via stored procedures and views → Power BI dashboard with six analytical pages.

Schema Design

13 interrelated tables covering the full customer journey — from acquisition through purchase to ad attribution:

  • Users — demographics, signup dates, activity history
  • Products & Inventory — catalog, pricing, stock levels
  • Orders & Order Details — transactional data with order-line granularity
  • Digital Campaigns & Ads — campaign structure, budget allocation, placement types
  • Ad Interactions — reach → click → lead → conversion funnel stages
  • Sessions — traffic source tracking, user session mapping
  • Ad Pricing — cost-per-placement by format and platform

All tables are connected via foreign key constraints. Data generation was calibrated to reflect realistic conversion probabilities, purchase behaviors, and budget dynamics rather than uniform random distributions.

Entity Relationship Diagram — 13-table schema

SQL Automation

Stored procedures handle computed fields that would otherwise require repeated ad-hoc queries — making the database self-maintaining as new data is inserted:

  • Total payment calculation per order (summing line items with applied discounts)
  • Ad budget computation: reach × placement pricing from the ad pricing table
  • Campaign aggregate metrics: total budget, click counts, lead counts, revenue
  • Funnel interaction metrics: reach → click → lead → conversion rates per campaign

Seven analytical views abstract the join logic for Power BI consumption: user order summaries, ad performance metrics, campaign ROI calculations, funnel stage indicators, revenue by product category, conversion rates by traffic source, and ad efficiency rankings. The CTEs inside several views use window functions (ROW_NUMBER(), LAG()) to compute cohort retention and first-purchase attribution.

Power BI Dashboard

Six dashboard pages, each targeting a specific business question:

  • User Insights: demographics, platform usage, city distribution, active vs. new user segmentation
  • Products: category mix, stock levels, price distribution, low-stock alerts
  • Orders: revenue trends, payment method breakdown, geographic revenue attribution, top-product rankings
  • Campaigns: performance metrics, conversion rate comparisons, profitability, CTR by campaign type
  • Ad Structure: format distribution, platform allocation, budget split, active status overview
  • Ad Performance: full funnel metrics, click-to-lead ratios, ROAS (Return on Ad Spend), platform-level CTR benchmarks
